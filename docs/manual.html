1. Qué es y qué resuelve

Una impresora fiscal sólo puede estar conectada a un equipo y sólo puede imprimir un documento a la vez. Cuando varias cajas emiten, aparecen tres problemas clásicos:

  • Correlativos duplicados: dos cajas creen que la siguiente factura es la misma.
  • Facturas mezcladas: los ítems de una caja se imprimen dentro de la factura de otra.
  • Sin auditoría: nadie sabe qué estación emitió qué documento ni cuándo.

El spooler fiscal es un servicio central que se queda con la impresora. Las estaciones (Profit Plus) ven un puerto COM virtual; el agente de cada estación transporta los bytes al servidor, y el servidor los ejecuta en orden, uno por uno, manteniendo el correlativo y el historial en SQLite.

Una cola, un escritor

Sólo el servidor escribe en la impresora. Nunca hay dos manos sobre el mismo puerto.

Turno por factura

La caja que abre una factura conserva el turno hasta cerrarla: nada se intercala.

Sin reenvío ciego

Si un comando pudo imprimirse, no se reintenta: se evita la doble emisión.

API para otros sistemas

Ecommerce, ERP web o CRM pueden facturar por HTTP sin hablar COM ni gRPC.

Qué incluye

  • server.exe: cola, guardián de estado, SQLite, gRPC para las estaciones y API REST.
  • agent.exe: puente entre el COM virtual de cada caja y el servidor.
  • Driver fiscal TFHKA (The Factory HKA, ASCII), aislado para poder añadir otras marcas.
  • Servicios de Windows, scripts de instalación, logs con rotación y manual (este documento).
  • Ejemplos de integración en curl, PHP, Go, Python, Node.js y Rust.

                                             │ HTTP
                                 ecommerce · ERP web · CRM

El recorrido de una factura

  1. Profit Plus escribe en COM3. Cree que habla con una impresora; en realidad habla con un extremo de com0com.
  2. El agente lee COM4. Delimita la trama por silencio (no interpreta el protocolo) y la envía por gRPC al servidor con el token.
  3. El servidor encola. Cada estación tiene su cola; una sola estación tiene el turno en cada momento.
  4. Se escribe en la impresora. El servidor envía el comando, lee la respuesta íntegra y la devuelve a la estación.
  5. Se registra. Si la respuesta es una factura, guarda tipo, número, estación, hashes y latencia. Detecta números repetidos.

Conceptos clave

ConceptoQué significa en la práctica
EstaciónUn equipo con Profit Plus y un agente. Se identifica con station_id (por ejemplo CAJA-01).
Turno exclusivoLa primera línea de ítem abre una factura y retiene la impresora hasta el cierre (101). Las demás cajas esperan.
CorrelativoLo asigna la impresora; el servidor lo registra y detecta si un número se repite (doble emisión).
GuardiánSi hay papel agotado, memoria fiscal llena o un error fiscal, el servidor rechaza la emisión antes de escribir.
IdempotenciaEn REST, una Idempotency-Key repetida devuelve la respuesta guardada sin volver a imprimir.
Turno abandonadoSi una caja muere con una factura abierta, el turno se libera tras document_lock_timeout_ms.
Importante El agente no interpreta nada de fiscalidad: transporta bytes. Todo el criterio (turno, correlativo, estado) vive en el servidor, junto a la impresora.

3. Puesta en marcha

Requisitos

  • Windows 10/11 o Server 2019/2022, 64 bits.
  • Go 1.25 o superior sólo para compilar; los binarios no necesitan Go.
  • Impresora fiscal TFHKA con puerto serie (o adaptador USB-serie).
  • Driver com0com en cada estación (par de puertos virtuales).
  • Permisos de administrador para instalar servicios y com0com.
  • Puerto 5050 (gRPC) abierto entre estaciones y servidor; 8080 si usa la API REST.

Compilar

cd C:\Proyectos\GO\SpoolerFiscal
.\scripts\build.ps1powershell

También puede usar build.bat o compilar a mano:

go build -trimpath -ldflags "-s -w" -o bin\agent.exe  .\cmd\agentbash

Los binarios quedan en bin\. Son autocontenidos: no requieren DLLs ni runtime adicional.

3.1 Configurar el servidor

Copie configs\server.yaml junto al binario y ajuste al menos el token y el puerto de la impresora:

listen: 0.0.0.0:5050            # gRPC para las estaciones
token: CAMBIAR-ESTE-TOKEN       # el mismo en todos los agentes

printer:
  driver: tfhka
  transport: serial             # serial | tcp (tcp = laboratorio)
  port:
    name: COM1
    baud_rate: 9600
    data_bits: 8
    parity: none
    stop_bits: "1"
  command_terminator: "\r\n"    # CR+LF: con CR solo la TFHKA no responde
  response_timeout_ms: 20000

queue:
  max_pending: 256
  default_timeout_ms: 30000
  document_lock_timeout_ms: 120000

http:
  enabled: true                 # API REST para ecommerce/ERP/CRM
  listen: 0.0.0.0:8080

database:
  path: data/spooler.dbyaml
Token Cámbielo en producción. Puede dejarlo fuera del YAML y usar la variable de entorno SPOOLER_TOKEN. El servicio restringe los permisos del archivo al arrancar.

3.3 Crear el par de puertos virtuales

Instale com0com y cree un par, por ejemplo COM3 ↔ COM4. Profit Plus usará COM3; el agente abrirá COM4. El script scripts\setup-com0com.ps1 ayuda a crearlo.

Por qué un par Profit Plus necesita un puerto COM real del sistema. com0com es un driver existente; el proyecto no implementa emulación de kernel.

3.4 Apuntar Profit Plus

En Profit Plus, configure la impresora fiscal como The Factory, puerto COM3, 9600 8N1, sin control de flujo. Consulte docs\PROFITPLUS.md para el detalle por versión.

3.1 API REST

La API vive dentro de server.exe y comparte cola, turno y correlativo con las estaciones. Se habilita con http.enabled: true. Todas las rutas salvo la salud exigen el token compartido.

Autenticación

Authorization: Bearer CAMBIAR-ESTE-TOKENhttp

También se acepta X-Spooler-Token. Si la API cruza la red de la empresa, active tls.enabled: el servidor sirve HTTPS con el mismo certificado.

Endpoints

MétodoRutaPara qué
GET/v1/healthSalud y versión, sin token.
GET/v1/statusImpresora, cola, documento abierto y contadores. ?probe=true consulta el hardware.
GET/v1/printerModelo, serial, RIF, firmware y memoria fiscal.
GET/v1/documentsHistorial fiscal (?limit=50).
POST/v1/commandsUn comando fiscal suelto (sondas, reportes X/Z).
POST/v1/invoicesFactura completa con líneas TFHKA.
POST/v1/invoices/structuredFactura desde ítems y totales JSON; el servidor la compila.

Factura con líneas TFHKA

Para integraciones que ya generan el protocolo. La primera línea abre la factura y la última debe ser 101; el servidor valida la estructura antes de imprimir.

curl -X POST http://127.0.0.1:8080/v1/invoices \
  -H "Authorization: Bearer CAMBIAR-ESTE-TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: pedido-1001" \
  -d '{
    "station": "ECOM-01",
    "client_ref": "pedido-1001",
    "lines": ["!   1.000     10.00CAFE", "101"]
  }'bash

Idempotencia y reintentos

  • Envíe Idempotency-Key (el número de pedido es perfecto).
  • Misma clave y mismo cuerpo: devuelve la respuesta guardada, cabecera Idempotent-Replay: true y no imprime otra vez.
  • Misma clave y cuerpo distinto: 409 idempotency_conflict.
  • Sin clave, un reintento puede emitir una segunda factura.

Errores

HTTPCódigoQué hacer
400invalid_requestRevise el JSON, la estación o las líneas.
400totals_mismatchLos totales enviados no coinciden con los calculados.
401unauthorizedToken ausente o incorrecto.
403station_not_allowedLa estación no está en allowed_stations.
409printer_blockedPapel agotado, memoria llena o error fiscal.
429queue_fullCola llena: espere y reintente.
503printer_unavailableImpresora apagada o sin respuesta.
504timeoutVenció en la cola; ese comando no se imprimió.

3.2 Factura desde ítems y totales

Es la vía recomendada para ecommerce, ERP o CRM. Se envía la factura como ítems; el servidor genera las líneas TFHKA, valida el total y ejecuta la factura de forma atómica.

curl -X POST http://127.0.0.1:8080/v1/invoices/structured \
  -H "Authorization: Bearer CAMBIAR-ESTE-TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: pedido-1001" \
  -d '{
    "station": "ECOM-01",
    "client_ref": "pedido-1001",
    "items": [
      {"description": "CAFE", "quantity": 1, "unit_price": 10.00, "tax": "general"},
      {"description": "PAN",  "quantity": 2, "unit_price": 5.00,  "tax": "reduced"}
    ],
    "totals": {"subtotal": 17.88, "tax": 2.12, "total": 20.00}
  }'bash

Respuesta (201 Created):

{
  "station": "ECOM-01",
  "order_ref": "pedido-1001",
  "completed": true,
  "invoice_number": 1,
  "document_type": "invoice",
  "sequence": 1,
  "compiled_lines": [
    "!   1.000     10.00CAFE",
    "\"   2.000      5.00PAN",
    "101"
  ],
  "totals": {"subtotal": 17.88, "tax": 2.12, "total": 20.00},
  "document": {
    "number": 1,
    "response_text": "0|Factura 1|Total: 20.00|Impreso:1"
  }
}json

Reglas de compilación

taxPrefijo TFHKAAlícuota
general (omisión)!16 %
reduced"8 %
additional#30 %
exemptespacio0 %
  • unit_price es el precio con IVA incluido, como lo maneja la TFHKA.
  • quantity: 0.001 a 9999.999 (tres decimales). unit_price: 0 a 9.999.999,99.
  • description: ASCII imprimible, máximo 40 caracteres, sin | ni saltos de línea. Se rechaza cualquier intento de inyectar comandos.
  • totals es opcional. Si lo envía, total es obligatorio y se compara con el calculado (tolerancia de un centavo); subtotal y tax se comparan sólo si son mayores que cero. Una diferencia responde 400 totals_mismatch y no imprime.
  • No incluye cliente ni formas de pago: para RIF, nombre, pagos o notas de crédito use /v1/commands.
Consejo Guarde el invoice_number y el issued_at devueltos junto al pedido. Son los datos fiscales que su sistema debe conservar.

Referencia de cada línea: client_ref#índice

Una factura no es un solo comando: son los ítems, el cierre 101 y, si los hay, los comandos adicionales. El servidor registra cada uno en documents con una referencia propia, formada por su client_ref y el índice de la línea:

pedido-1001#0   primer ítem   (! 1.000 10.00CAFE)
pedido-1001#1   segundo ítem  (" 2.000 5.00PAN)
pedido-1001#2   cierre        (101)texto

El índice empieza en 0 y coincide con la posición en compiled_lines. El objeto document de la respuesta corresponde a la última línea que generó documento —el cierre—, por eso muestra "client_ref": "pedido-1001#2" aunque usted haya enviado pedido-1001. No es un error y no afecta a la idempotencia, que sigue dependiendo de Idempotency-Key. Si no envía client_ref ni clave, la referencia queda vacía y no se añade sufijo. Para no perder el dato original, la respuesta incluye order_ref con el client_ref tal como lo envió (o la Idempotency-Key si no envió ninguno).

4.1 cURL (bash)

La forma más rápida de comprobar que el servidor responde. Guarde esto como invoice.sh:

#!/usr/bin/env bash
set -euo pipefail

SPOOLER_URL="${SPOOLER_URL:-http://127.0.0.1:8080}"
: "${SPOOLER_TOKEN:?Defina SPOOLER_TOKEN con el token del spooler}"
STATION="${STATION:-ECOM-01}"
ORDER_ID="${ORDER_ID:-pedido-1001}"

payload=$(cat <<JSON
{
  "station": "${STATION}",
  "client_ref": "${ORDER_ID}",
  "items": [
    {"description": "CAFE", "quantity": 1, "unit_price": 10.00, "tax": "general"},
    {"description": "PAN",  "quantity": 2, "unit_price": 5.00,  "tax": "reduced"}
  ]
}
JSON
)

response=$(curl -sS -w '\n%{http_code}' -X POST "${SPOOLER_URL}/v1/invoices/structured" \
  -H "Authorization: Bearer ${SPOOLER_TOKEN}" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: ${ORDER_ID}" \
  -d "${payload}")

status="${response##*$'\n'}"
body="${response%$'\n'*}"

if [ "${status}" != "201" ]; then
  echo "ERROR ${status}: ${body}" >&2
  exit 1
fi

echo "${body}" | jq -r '"Factura \(.invoice_number) emitida: total \(.totals.total)"'bash

chmod +x invoice.sh
SPOOLER_TOKEN=CAMBIAR-ESTE-TOKEN ./invoice.shbash

4.3 PHP 8+

Requiere la extensión curl (incluida en las builds de PHP para Windows; en Linux, php-curl).

<?php
declare(strict_types=1);

$base    = getenv('SPOOLER_URL') ?: 'http://127.0.0.1:8080';
$token   = getenv('SPOOLER_TOKEN') ?: '';
$station = getenv('STATION') ?: 'ECOM-01';
$order   = getenv('ORDER_ID') ?: 'pedido-1001';

if ($token === '') {
    fwrite(STDERR, "Defina SPOOLER_TOKEN con el token del spooler.\n");
    exit(1);
}

$payload = [
    'station'    => $station,
    'client_ref' => $order,
    'items'      => [
        ['description' => 'CAFE', 'quantity' => 1, 'unit_price' => 10.00, 'tax' => 'general'],
        ['description' => 'PAN',  'quantity' => 2, 'unit_price' => 5.00,  'tax' => 'reduced'],
    ],
];

$ch = curl_init($base . '/v1/invoices/structured');
curl_setopt_array($ch, [
    CURLOPT_POST           => true,
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_TIMEOUT        => 60,
    CURLOPT_HTTPHEADER     => [
        'Authorization: Bearer ' . $token,
        'Content-Type: application/json',
        'Idempotency-Key: ' . $order,
    ],
    CURLOPT_POSTFIELDS     => json_encode($payload, JSON_UNESCAPED_UNICODE),
]);

$body   = curl_exec($ch);
$status = (int) curl_getinfo($ch, CURLINFO_HTTP_CODE);
$error  = curl_error($ch);
curl_close($ch);

if ($body === false) {
    fwrite(STDERR, "Error de red: {$error}\n");
    exit(1);
}
if ($status !== 201) {
    fwrite(STDERR, "ERROR {$status}: {$body}\n");
    exit(1);
}

$factura = json_decode($body, true, 512, JSON_THROW_ON_ERROR);
printf(
    "Factura %d emitida: total %.2f (secuencia %d)\n",
    $factura['invoice_number'],
    $factura['totals']['total'],
    $factura['sequence']
);php

Ejecución:

    if err != nil {

        os.Exit(1)
    }
    req.Header.Set("Authorization", "Bearer "+token)
    req.Header.Set("Content-Type", "application/json")
    req.Header.Set("Idempotency-Key", order)

    client := &http.Client{Timeout: 60 * time.Second}
    resp, err := client.Do(req)
    if err != nil {
        fmt.Fprintln(os.Stderr, "red:", err)
        os.Exit(1)
    }
    defer resp.Body.Close()
    data, _ := io.ReadAll(resp.Body)

    if resp.StatusCode != http.StatusCreated {
        fmt.Fprintf(os.Stderr, "ERROR %d: %s\n", resp.StatusCode, data)
        os.Exit(1)
    }

    var out struct {
        InvoiceNumber int64 `json:"invoice_number"`
        Sequence      int64 `json:"sequence"`
        Totals        struct {
            Total float64 `json:"total"`
        } `json:"totals"`
        Document *struct {
            ResponseText string `json:"response_text"`
        } `json:"document"`
    }
    if err := json.Unmarshal(data, &out); err != nil {
        fmt.Fprintln(os.Stderr, "JSON:", err)
        os.Exit(1)
    }

    fmt.Printf("Factura %d emitida: total %.2f (secuencia %d)\n",
        out.InvoiceNumber, out.Totals.Total, out.Sequence)
    if out.Document != nil && out.Document.ResponseText != "" {
        fmt.Printf("Impresora: %s\n", out.Document.ResponseText)
    }

4.5 Python 3.10+

Sin dependencias: usa urllib de la biblioteca estándar, así que no hace falta pip install.

#!/usr/bin/env python3
import json
import os
import sys
import urllib.error
import urllib.request


def env(key: str, default: str) -> str:
    return os.environ.get(key) or default


def main() -> int:
    base = env("SPOOLER_URL", "http://127.0.0.1:8080").rstrip("/")
    station = env("STATION", "ECOM-01")
    order = env("ORDER_ID", "pedido-1001")
    token = os.environ.get("SPOOLER_TOKEN", "")
    if not token:
        print("Defina SPOOLER_TOKEN.", file=sys.stderr)
        return 1

    payload = {
        "station": station,
        "client_ref": order,
        "items": [
            {"description": "CAFE", "quantity": 1, "unit_price": 10.00, "tax": "general"},
            {"description": "PAN", "quantity": 2, "unit_price": 5.00, "tax": "reduced"},
        ],
    }
    req = urllib.request.Request(
        f"{base}/v1/invoices/structured",
        data=json.dumps(payload).encode("utf-8"),
        method="POST",
        headers={
            "Authorization": f"Bearer {token}",
            "Content-Type": "application/json",
            "Idempotency-Key": order,
        },
    )

    try:
        with urllib.request.urlopen(req, timeout=60) as resp:
            status = resp.status
            body = resp.read().decode("utf-8")
    except urllib.error.HTTPError as exc:
        print(f"ERROR {exc.code}: {exc.read().decode('utf-8', 'replace')}", file=sys.stderr)
        return 1
    except urllib.error.URLError as exc:
        print(f"Error de red: {exc.reason}", file=sys.stderr)
        return 1

    if status != 201:
        print(f"ERROR {status}: {body}", file=sys.stderr)
        return 1

    factura = json.loads(body)
    print(
        f"Factura {factura['invoice_number']} emitida: "
        f"total {factura['totals']['total']:.2f} (secuencia {factura['sequence']})"
    )
    texto = (factura.get("document") or {}).get("response_text", "")
    if texto:
        print(f"Impresora: {texto}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())python

5. Operación diaria

Logs

ArchivoQué contiene
logs\server.logSesiones, documentos registrados, bloqueos del guardián, métricas cada minuto y errores de impresora.
logs\agent.logApertura del COM virtual, reconexiones, reintentos y contadores de tramas.

La rotación se configura en logging (max_size_mb, max_backups, max_age_days, compress). Suba a debug sólo para diagnosticar: genera mucho volumen.

Qué mirar cada día

curl -H "Authorization: Bearer TOKEN" http://servidor:8080/v1/statusbash
  • online: la impresora responde.
  • blocked_reason: papel agotado, memoria llena o error fiscal.
  • duplicates_detected: si sube, hubo un número repetido; revise el log.
  • queue_depth: cola acumulada. Con una impresora real, 10 facturas en cola son ~20 segundos.

Respaldo

Todo el historial fiscal vive en data\spooler.db (SQLite en modo WAL). Para un respaldo consistente:

  1. Detenga el servicio: sc stop SpoolerFiscalServer.
  2. Copie la carpeta data\ completa (incluye .db-wal y .db-shm).
  3. Vuelva a iniciarlo: sc start SpoolerFiscalServer.

La tabla documents no se purga nunca; command_log se recorta según database.retention_days.

Permisos

Al arrancar, el servicio restringe la ACL del YAML (contiene el token) y de data\ a SYSTEM, Administradores y el usuario que ejecuta. Si corre en consola, hágalo como administrador o como el usuario que instaló: el token ya no es legible por el grupo Usuarios.

Actualizar

  1. Detenga servidor y agentes.
  2. Reemplace los .exe (guarde una copia de los anteriores).
  3. Revise el YAML: las claves nuevas tienen valores por omisión.
  4. Inicie el servidor, verifique /v1/health y emita una factura de prueba.
  5. Actualice los agentes uno por uno.

6. Seguridad

  • Token compartido: es la única credencial de estaciones y REST. Use uno largo y distinto por instalación. Se puede inyectar con SPOOLER_TOKEN sin escribirlo en el YAML.
  • HTTPS: active tls.enabled con certificado y clave. Para gRPC, tls.ca_file activa mTLS entre agente y servidor. La REST usa el mismo certificado pero autentica por token.
  • Firewall: abra 5050 y 8080 sólo hacia la red de la empresa. No exponga la API a Internet.
  • Lista blanca: allowed_stations limita qué estaciones pueden abrir sesión.
  • Permisos: el YAML y data\ quedan restringidos; no los copie a equipos de usuarios.
  • Auditoría: no borre documents. Es su respaldo ante una discrepancia fiscal.
Si se filtra el token Detenga el servidor, cambie token en el YAML y en todos los agentes, y reinicie. Las sesiones abiertas dejan de valer.

7. Problemas frecuentes

SíntomaCausa probableSolución
«La impresora no respondió» y el comando no se reenvía Terminador incorrecto o cable/puerto. Use command_terminator: "\r\n". Con \r solo la TFHKA no responde. Revise baudios y cable.
El agente repite «Serial port not found» COM virtual cerrado o com0com no instalado. Cree el par con com0com y confirme que virtual_com.name es el extremo del agente (COM4).
Profit Plus no imprime pero el agente está vivo Otro programa tiene abierto COM3, o parámetros distintos. Cierre el otro programa y use 9600 8N1 sin control de flujo en ambos extremos.
401 unauthorized Token ausente o distinto. Copie el mismo token en servidor y agentes; revise SPOOLER_TOKEN.
403 station_not_allowed La estación no está en la lista blanca. Añádala a allowed_stations o deje la lista vacía.
409 printer_blocked Papel agotado, memoria fiscal llena o error fiscal. Resuelva en la impresora; el bloqueo se libera con la siguiente respuesta limpia.
409 idempotency_conflict La clave ya se usó con otro cuerpo. Use una clave distinta por pedido; no reutilice la de otra factura.
429 queue_full Más comandos pendientes que max_pending. Espere unos segundos y reintente; revise si la impresora está lenta o bloqueada.
504 timeout Venció en la cola; el comando no se imprimió. Suba default_timeout_ms (60-90 s en ráfagas) y reintente con la misma clave.
Facturas de dos cajas mezcladas Versión antigua o dos servidores sobre la misma impresora. Un solo servidor por impresora. Actualice: el turno por factura impide el intercalado.
«Doble emisión detectada» en el log La impresora devolvió un número ya registrado. No borre el registro. Investigue el pedido; el original se conserva en documents.
/docs responde 404 La API REST está apagada. Active http.enabled: true y reinicie el servidor.
El servicio no arranca Config inválida, puerto ocupado o permisos. Ejecute en consola con -console para ver el error; revise logs\server.log.

8. Preguntas frecuentes

¿Puedo tener dos impresoras fiscales?

Un servidor atiende una impresora. Para dos, ejecute dos instancias con puertos, bases y tokens distintos, y asigne cada estación a la suya.

¿Sirve para otra marca?

Hoy sólo TFHKA (The Factory HKA, ASCII). El driver está aislado en internal/fiscal; otra marca requiere un driver nuevo (por ejemplo IxBatch) y validación con el hardware.

¿Puedo facturar sin Profit Plus?

Sí. La API REST existe justamente para eso: ecommerce, ERP web o CRM envían la factura por HTTP. El agente y com0com sólo son necesarios para las cajas con Profit Plus.

¿Qué pasa si se cae el servidor?

Las estaciones no pueden emitir: el agente reintenta con backoff y el comando no se pierde si aún no se escribió. Al volver el servidor, el correlativo y el historial se recuperan de SQLite. Un comando que ya se escribió no se reenvía.

¿Se pueden perder facturas?

El servidor registra cada documento con hashes de comando y respuesta. Si la impresora se corta después de escribir, el log lo advierte y no reintenta para evitar una doble emisión; el operador debe revisar el papel.

¿Cuántas cajas soporta?

El límite es la impresora: 0,3-1 factura por segundo. Diez cajas con ráfagas funcionan, pero la última espera. Ajuste los timeouts; la cola admite 256 comandos por omisión.

¿La API REST es la misma cola que Profit Plus?

Sí. Comparten cola, turno por factura, guardián y correlativo. Un pedido de ecommerce y una factura de caja no se pisan.

¿Cómo pruebo sin impresora?

Use el simulador del proyecto SimuladorFiscalGO con printer.transport: tcp y tcp_address: 127.0.0.1:2011. Todos los ejemplos funcionan contra él.

Este manual, docs\API.md (guía REST), api\openapi.yaml (contrato), docs\INSTALACION.md, docs\OPERACION.md, docs\PROTOCOLO_TFHKA.md y docs\PROFITPLUS.md.
