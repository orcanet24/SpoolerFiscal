Spooler Fiscal — Manual paso a paso

Lo que se hace en el servidor (la PC con la impresora) y lo que se hace en el cliente (la PC con Profit Plus).

Versión 1.0.0 · Impresora TFHKA por puerto serie · API HTTP · COM virtual con com0com.

SERVIDOR: COM1 + HTTP 8080 CLIENTE: COM3 + agente HTTP
1. Resumen 2. Requisitos 3. PARTE A — Servidor 4. PARTE B — Cliente 5. Viaje de una factura 6. Operación diaria 7. Problemas frecuentes 8. Seguridad y respaldo

1. Resumen: qué es cada parte

Servidor

PC donde está conectada la impresora fiscal por cable serie.

  • Abra el COM1 y escribe en la impresora.
  • Mantiene la cola y el correlativo.
  • Guarda la auditoría en SQLite.
  • Publica una API HTTP en el puerto 8080.

Cliente / estación

PC donde corre Profit Plus (cada caja).

  • Crea un COM virtual (com0com).
  • El agente lee ese COM y lo convierte en HTTP.
  • Habla con el servidor en el puerto 8080.
  • Profit Plus cree que tiene una impresora en COM3.

Diagrama

arquitectura CLIENTE (caja)                                    SERVIDOR (impresora)
┌──────────────────────────────┐              ┌──────────────────────────────┐
│ Profit Plus                  │              │ server.exe                   │
│   └─ COM3 (virtual)          │              │   ├─ cola serializada        │
│        ▲                     │              │   ├─ turno por factura       │
│        │ par com0com         │   HTTP 8080  │   ├─ correlativo             │
│        ▼                     │ ───────────► │   ├─ SQLite auditoría        │
│ agent.exe ──► COM4 ──────────┼──────────────┤   └─ API HTTP /v1            │
└──────────────────────────────┘              │            │                 │
                                              │            ▼ COM1            │
                                              │      Impresora TFHKA         │
                                              └──────────────────────────────┘

También por HTTP 8080: ecommerce · ERP web · CRM
Idea clave: el agente no interpreta el protocolo fiscal. Sólo transporta bytes entre el COM virtual y el servidor. Todo el criterio (turno, correlativo, papel, memoria) vive en el servidor, junto a la impresora.

2. Requisitos

  • Windows 10/11 o Windows Server 2019/2022, 64 bits.
  • Servidor: impresora fiscal TFHKA / The Factory conectada por puerto serie (COM1) o adaptador USB-serie.
  • Cliente: Profit Plus y el driver com0com (crea el puerto COM virtual).
  • Go 1.26+ sólo en la máquina donde compiles; los .exe no necesitan Go.
  • Permisos de administrador para instalar servicios, com0com y abrir el firewall.
  • Red local: el servidor debe alcanzar el COM1 y las estaciones deben alcanzar el puerto 8080 del servidor.
Solo TFHKA. El único driver implementado es tfhka (The Factory HKA, protocolo ASCII). Otros modelos requerirían un driver nuevo.
Parte A — Servidor

3. Instalar y configurar el servidor

A.1 ¿Qué hace el servidor?

  1. Abra el puerto COM1 donde está la impresora fiscal.
  2. Escucha la API HTTP en 8080.
  3. Recibe comandos de los agentes y de sistemas externos, los encola y los ejecuta de uno en uno.
  4. Aplica el turno por factura: la caja que abre una factura no la suelta hasta cerrarla.
  5. Registra cada documento en data\spooler.db (auditoría).

A.2 Archivos que se usan

estructura sugerida en el servidorC:\SpoolerFiscal\
├─ bin\
│   └─ server.exe
├─ configs\
│   └─ server.yaml
├─ data\          ← la crea el servicio (base SQLite)
└─ logs\          ← la crea el servicio (server.log)

A.3 Configurar server.yaml

Copia configs\server.yaml del repositorio y ajusta como mínimo el token y el COM:

server.yamltoken: CAMBIAR-ESTE-TOKEN        # el mismo que usarán todos los agentes

printer:
  driver: tfhka
  transport: serial             # serial = impresora física (tcp = laboratorio)
  port:
    name: COM1                  # puerto real de la impresora
    baud_rate: 9600
    data_bits: 8
    parity: none
    stop_bits: "1"
    flow_control: none
  command_terminator: "\r\n"    # CR+LF: con CR solo la TFHKA no responde
  response_timeout_ms: 20000

http:
  listen: 0.0.0.0:8080          # único puerto: agentes y sistemas externos

database:
  path: data/spooler.db         # relativo al directorio de trabajo del servicio
Claves eliminadas. Si tu server.yaml viene de una versión anterior, borra estas líneas o el servidor rechazará el archivo: listen, session_ttl_minutes, http.enabled. Ya no existen.

A.4 Probar en consola (antes de instalar el servicio)

1

Detén el servicio si estaba corriendo

powershellsc stop SpoolerFiscalServer
2

Ejecuta en primer plano

powershellcd C:\SpoolerFiscal
.\bin\server.exe -console -config .\configs\server.yaml
3

Debes ver algo así

loginiciando spooler fiscal version=1.0.0 config=C:\SpoolerFiscal\configs\server.yaml
impresora fiscal configurada driver=tfhka transporte=serial destino=COM1 @ 9600 8N1
cola de impresión iniciada max_pendientes=256 driver=tfhka
spooler fiscal escuchando addr=[::]:8080 tls=false driver=tfhka
api HTTP escuchando addr=[::]:8080 docs=/docs/API.md

Si ves reintentando abrir la impresora, revisa que el COM1 sea el correcto y que la impresora esté encendida.

A.5 Abrir el puerto en el firewall

powershell (administrador)New-NetFirewallRule -DisplayName "Spooler Fiscal HTTP" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow

A.6 Instalar como servicio de Windows

powershell (administrador).\scripts\install-server.ps1 -Root C:\SpoolerFiscal
sc start SpoolerFiscalServer

El servicio arranca solo al encender la PC y se reinicia si falla.

A.7 Verificar que responde

bashcurl http://127.0.0.1:8080/v1/health
# {"status":"ok","version":"1.0.0","protocol_version":1,"driver":"tfhka", ...}

curl -H "Authorization: Bearer CAMBIAR-ESTE-TOKEN" http://127.0.0.1:8080/v1/status
/v1/health es público. Todas las demás rutas exigen el token.

A.8 Dónde mirar si algo falla

  • logs\server.log — arranque, errores de impresora, documentos emitidos.
  • En el log debes ver documento fiscal registrado al emitir una factura.
  • Cada minuto escribe una línea métricas (documentos, cola, estado).
Parte B — Cliente / estación

4. Instalar y configurar el cliente (Profit Plus)

B.1 ¿Qué hace el cliente?

  1. Crea un par de puertos COM virtuales con com0com: COM3 ↔ COM4.
  2. Profit Plus se configura contra COM3 (9600 8N1).
  3. agent.exe abre COM4, lee las tramas y las envía por HTTP al servidor.
  4. El servidor devuelve la respuesta de la impresora y el agente la escribe en COM4.
Resultado: Profit Plus ve una impresora fiscal normal en COM3, pero en realidad está hablando por la red con el servidor.

B.2 Crear el par de puertos virtuales (com0com)

1

Instalar com0com

Descárgalo de https://sourceforge.net/projects/com0com/ e instálalo.

2

Crear el par con el script del proyecto

powershell (administrador).\scripts\setup-com0com.ps1 -ProfitPort COM3 -AgentPort COM4

Equivalentes manuales:

cmd"C:\Program Files (x86)\com0com\setupc.exe" install PortName=COM3 PortName=COM4
3

Comprobar el par

En el Administrador de dispositivos → Puertos (COM y LPT) deben aparecer COM3 y COM4 emparejados.

Si COM3/COM4 están ocupados, usa otros (por ejemplo COM11/COM12) y ajusta el agent.yaml y Profit Plus.

estructura sugerida en la estaciónC:\SpoolerFiscal\
├─ bin\

├─ configs\

B.4 Configurar agent.yaml

agent.yamlstation_id: CAJA-01                 # único por estación (aparece en la auditoría)

server:
  address: http://192.168.1.10:8080   # URL de la API del servidor
  token: CAMBIAR-ESTE-TOKEN           # el mismo del servidor
  request_timeout_ms: 30000

virtual_com:
  name: COM4                          # extremo del agente (Profit Plus usa COM3)
  baud_rate: 9600
  data_bits: 8
  parity: none
  stop_bits: "1"
  flow_control: none

bridge:
  read_gap_ms: 30
  response_timeout_ms: 15000
  offline_response_hex: ""            # vacío = Profit Plus ve timeout
  log_hex_payloads: false             # true = registra bytes en hexadecimal

logging:
  level: info
  file: logs/agent.log
  console: true                       # false cuando corra como servicio
Claves eliminadas. Si tu agent.yaml es antiguo, borra dial_timeout_ms. Ya no existe.

B.5 Probar el agente en consola

powershell.\bin\agent.exe -console -config .\configs\agent.yaml

Debes ver:

logagente iniciado estacion=CAJA-01 servidor=http://192.168.1.10:8080 com_virtual=COM4
COM virtual abierto puerto=COM4 baudios=9600 trama=8N1
conectado al spooler servidor=http://192.168.1.10:8080
El agente no necesita que el servidor exista al arrancar: si no está, lo reintentará solo cada 30 s y avisará conectado al spooler cuando aparezca.

B.6 Apuntar Profit Plus

  1. Impresora fiscal: marca The Factory / protocolo TFHKA.
  2. Puerto: COM3.
  3. Velocidad: 9600, 8 datos, sin paridad, 1 bit de parada.
  4. Control de flujo: ninguno.

Detalle por versión en docs\PROFITPLUS.md.

B.7 Instalar el agente como servicio

powershell (administrador).\scripts\install-agent.ps1 -Root C:\SpoolerFiscal
sc start SpoolerFiscalAgent

B.8 Verificar de extremo a extremo

  1. En el servidor, logs\server.log debe aparecer sesión/documento al usar Profit Plus.
  2. Emita una factura de prueba desde Profit Plus.
  3. En el servidor debe aparecer documento fiscal registrado con tipo, número y estación.
  4. En la estación, el agente registra documento registrado por el spooler.

5. El viaje de una factura, paso a paso

  1. Profit Plus escribe en COM3 el primer comando de la factura (la primera línea de ítem abre el documento).
  2. com0com entrega esa trama por COM4.
  3. agent.exe lee la trama (la delimita por silencio, sin interpretarla) y hace un POST /v1/commands al servidor con los bytes en base64.
  4. server.exe encola el comando. Si otra caja tiene el turno, espera.
  5. El servidor escribe el comando en el COM1 y lee la respuesta íntegra de la impresora.
  6. El servidor registra el documento si corresponde (tipo, número, hashes, estación) y devuelve la respuesta.
  7. agent.exe recibe la respuesta y la escribe en COM4.
  8. com0com la entrega a COM3 y Profit Plus la lee como si viniera de su impresora.
  9. Al enviar Profit Plus el cierre 101, se repite el viaje y el servidor libera el turno para la siguiente factura.
Un solo escritor: sólo el servidor escribe en la impresora. Nunca hay dos cajas escribiendo a la vez.

Estado y monitoreo

bashcurl http://127.0.0.1:8080/v1/health
curl -H "Authorization: Bearer <token>" http://127.0.0.1:8080/v1/status

/v1/status devuelve: impresora (online, papel, memoria), cola, documento abierto, propietario del turno y motivo de bloqueo.

Logs

  • Servidor: logs\server.log (rotación: 20 MB, 10 copias, 30 días).
  • Agente: logs\agent.log.
  • Nivel: level: debug | info | warn | error en el YAML.

Orden de arranque tras un apagón

  1. Enciende la impresora y verifica el papel.
  2. Arranca el servidor (servicio automático).
  3. Arrancan las estaciones (servicios automáticos); el agente se reconecta solo.

En el servidor

SíntomaCausa probableQué hacer
reintentando abrir la impresora cada 0,5 sNada escucha en el puerto configuradoCon transport: serial, revisa printer.port.name (COM1) y que la impresora esté encendida. Si usaste transport: tcp, ese modo es de laboratorio: vuelve a serial.

El servicio no escucha en 8080Puerto ocupado o http.listen vacíoRevisa http.listen y con netstat -ano | findstr :8080 quién lo ocupa.
401 unauthorized desde el agenteToken distintoIguala token en servidor y agentes (o usa SPOOLER_TOKEN).
403 estación no autorizadaallowed_stations no incluye el station_idAgrega la estación o deja la lista vacía.
409 printer_blockedPapel agotado, memoria llena o error fiscalResuelve en la impresora; el bloqueo se libera con la siguiente respuesta limpia.

SíntomaCausa probableQué hacer

8. Seguridad, respaldo y actualización

Seguridad

  • Token: cámbialo en producción. Es la única credencial. Puedes usar SPOOLER_TOKEN y no escribirlo en el YAML.
  • Firewall: abre sólo el 8080 hacia la red de la empresa. No expongas la API a Internet.
  • HTTPS: activa tls.enabled con cert_file y key_file si la red no es de confianza.
  • Permisos: el servicio restringe el acceso al YAML y a data\. No los copias a equipos de usuarios.
  • Lista blanca: allowed_stations limita qué estaciones pueden imprimir.

Respaldo

La base data\spooler.db es la evidencia del correlativo. Respáldala con el servicio detenido (o en caliente, SQLite en WAL mantiene consistencia):

powershellsc stop SpoolerFiscalServer
Copy-Item data\spooler.db "\\backup\spooler-$(Get-Date -Format yyyyMMdd).db"
sc start SpoolerFiscalServer

Actualización

  1. Detén los servicios.
  2. Respalda data\ y configs\.
  3. Reemplaza server.exe y agent.exe (misma versión en todos lados).
  4. Arranca primero el servidor y luego los agentes.
  5. Verifica /v1/health y una factura de prueba.
No reemplaces la impresora sin documentarlo. Cambiar la numeración invalida la auditoría: registra el cambio y respalda la base.
